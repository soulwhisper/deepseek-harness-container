## Completed in this pass

1. **Manager smoke fixed.** The final `pluginManager/listBundles` probe sent an
   array; the native gateway requires exactly one plain-object `args` field.
   All manager mutations and the market reinstall now pass.
2. **Profile link drift fixed.** `pnpm install --lockfile-only` records
   absolute `link:` specifiers as paths relative to the seed workspace. Once
   the profile was copied to `$DSH_HOME`, market installs rewrote immutable
   links against the wrong directory and the next restart failed.
   - Added `scripts/normalize-locks.mjs`; committed profile locks now carry
     absolute `link:/opt/dsh/runtime/...` versions.
   - The Docker `profile-locks` export normalizes generated locks.
   - `materialize-state.mjs` normalizes copied/merged locks, accepts equivalent
     resolved links, and repairs only dangling managed symlinks. A real
     directory or a symlink resolving elsewhere is still refused as shadowing.
   - Immutable symlinks are now limited to absolute `link:`/`file:`
     dependencies. Registry/git packages stay as writable profile copies so
     their own dependency lookup reaches the profile's override links. This
     fixed Tavern's `dsh-better-sidebar` → `@deepseek-ai/schemastery` failure.
   - Tavern's linked source now exposes the complete patched runtime closure in
     its own `node_modules/@deepseek-ai`, so peer imports such as `dsh-tools`
     resolve there instead of failing after Node follows the realpath.
   - `finalize-profile.mjs` removes ecosystem packages that declare no
     `dsh.bundle` from startup bundles (currently `dsh-tavern-knock-knock`)
     while keeping them installed as dependencies, matching native DSH
     behavior instead of logging a skip on every boot.
3. **Repository format split.** Local patches, the SSO plugin, image build,
   scaffold/test/docs and deploy examples now have separate trees, with layout
   checks in `scripts/verify.mjs`.
4. **Per-image release routes.** Web follows DSH, Tavern follows dsh-tavern.
   `versions.json` owns the release tags and image names; `publish.yaml` has
   independent `release-web` and `release-tavern` jobs.
5. **Deploy examples.** Docker Compose and Kubernetes examples were extracted
   from the README and validated locally.
6. **Docs.** English/Chinese READMEs, NOTICE, plugin notice, patch/build docs
   and `SOURCE-BUILD.txt` were updated for the new paths and tags.
7. **Repository automation.** `main` is protected (PR required, linear history,
   required `CI checks passed`, no force pushes, admins enforced, auto-merge
   disabled). No branch push publishes; only `web-*`/`tavern-*` release tags
   build, smoke and publish the matching multi-arch image on native
   amd64/arm64 runners. Added a Docker-free direct field test and scheduled workflow cleanup, labeler,
   label sync, CODEOWNERS, PR template, CodeRabbit config and Renovate.
   Renovate tracks the DSH npm upstream, the Tavern GitHub tag and
   `dshmarket`, but never auto-merges: every update gets `review/required`,
   and a version-only PR is expected to fail until the source commit, exact
   hashes, locks, release tags and docs are fixed by a human. Node/pnpm,
   ecosystem plugins and profile locks stay coupled manual pins.

## Release contract

| Target | Git release tag | Published image |
| --- | --- | --- |
| Web | `web-0.2.1-rc.2` | `ghcr.io/soulwhisper/dsh-web:0.2.1-rc.2` |
| Tavern | `tavern-3.0` | `ghcr.io/soulwhisper/dsh-tavern:3.0` |

A release tag is the only publication trigger. Each tag validates its exact
`versions.json.release.<target>.tag`, requires main ancestry, builds only that
target on native `ubuntu-24.04` and `ubuntu-24.04-arm` runners, runs the full
final-image smoke on both, pushes the two tested manifests to staging tags, and
combines them into one version index with a GitHub App token. No QEMU. Tags and
images are independent; no branch or candidate `sha-` images are published and
there is no `latest`.

Images:

- `localhost/dsh-web:local` — rebuilt; full final-image smoke passes:
  SSO rejection, protected manager, market install/reinstall, real
  Chromium/sidebar, native cookie across restart, mux lifetime, PTY, profile
  and source imports.
- `localhost/dsh-tavern:local` — rebuilt with the full runtime closure and
  bundle filtering; full final-image smoke passes with the same checks plus
  Tavern source download and Source HEAD/read-only behavior.
- Combined command `node scripts/smoke.mjs dsh-web:local dsh-tavern:local`
  passes both images in one run.
- arm64 is supported by the dependency graph: the runtime lock carries
  `@deepseek-ai/node-addon-system-linux-arm64`, the `@img/sharp-linux-arm64`
  optional package and arm64 variants for native modules. CI builds and
  full-smokes each target on native `ubuntu-24.04-arm`; the release job combines
  the two tested manifests without QEMU.
- Docker's tmpfs defaults to `noexec`, which broke the loader's `/tmp` native
  cache. The image sets `NARB_DISABLE_NATIVE_CACHE=1`, so addons load directly
  from the immutable prebuilt path. The CI verifier runs under the same
  read-only/cap-drop/tmpfs flags as the smoke and passes on both architectures.
- PR CI at `a1e7455` passed static checks, native amd64/arm64 web+tavern image
  builds and full smoke, the Docker-free field test on both architectures, and
  the required `CI checks passed` check. The labeler runs separately.
- `field-test.yaml` runs the production runtime closure directly on native
  runners and applies the exact-hash host/market patches; it is the Docker-free
  check for both architectures. It passed on `ubuntu-24.04` (x64) and
  `ubuntu-24.04-arm`.

Local smoke on NixOS needs Playwright's shared libraries. CI installs them via
`pnpm exec playwright install --with-deps chromium`; locally, Chromium launched
with an `LD_LIBRARY_PATH` built from the corresponding nixpkgs libraries
(`glib`, `nss`, `nspr`, `atk`, `cairo`, `pango`, `mesa`, `libxkbcommon`,
`libx11`, `libxcb`, `alsa-lib`, `cups`, `dbus`, `fontconfig`, and related
X11/GBM packages).
